# AGENTS.md — «Метрика»

Правила для всех агентов и людей, работающих в этом репозитории. Читать целиком до первой правки.
Глобальный `~/.config/opencode/AGENTS.md` действует поверх этих правил; при конфликте побеждает он.

## 1. Что за проект

Курсовой проект БГУИР: web-приложение оценки эффективности маркетинговых каналов с расчётом CAC, LTV и ROMI.
Клиент-серверное приложение на Node.js + Express + PostgreSQL, MVC, серверный рендер, React-острова.
Демо-бренд — «Метрика», демо-компания — интернет-магазин кофе «Зёрна» (Минск).

Источники истины (читать перед задачей):
1. `docs/superpowers/specs/2026-11-21-marketing-analytics-design.md` — архитектура, экраны, границы.
2. `docs/superpowers/specs/2026-11-21-metrics-spec.md` — формулы и краевые случаи.
3. `docs/superpowers/specs/2026-11-21-assignment-traceability.md` — требования бланка.

Если задача противоречит спеке — остановиться и сообщить, а не «улучшать» молча.

## 2. Нерушимые ограничения (из задания)

- **Только JavaScript**, без TypeScript и без `.ts`/`.tsx`. JSDoc приветствуется.
- **Одна таблица стилей** — `public/css/app.css`. Никаких вторых CSS-файлов, CSS-фреймворков, CSS-in-JS,
  styled-components, Tailwind, inline `<style>`. В React CSS не импортируется.
- **MVC**: Express-контроллеры, сервисы, репозитории, EJS-представления. Бизнес-логика — только в сервисах.
- **UI и все подписи — на русском**. Код, имена переменных, таблиц, классов, коммиты — английский.
- **Валюта — белорусский рубль (BYN)**, все суммы и демо-данные в BYN, рынок Беларуси, часовой пояс
  Europe/Minsk. Никаких `$`, `₽`, `руб.`, `рублей` в интерфейсе.
- **Один источник данных** — PostgreSQL. Никаких JSON-файлов как хранилища, localStorage для auth, in-memory БД
  в production-коде.
- **Работает на Windows 10** и на Linux; деплой через Docker и локальный PostgreSQL.
- **Ссылочная целостность** — FK/CHECK/UNIQUE обязательны; удаление истории клиентов и заказов запрещено.

## 3. Стек

| Что | Версия/правило |

**Модель субагентов:** все реализаторы и ревьюеры запускаются на модели владельца сессии —

Новую зависимость можно добавить только с обоснованием в задаче; проверять, что она не тянет TypeScript-сборку
и не приносит свой CSS.

## 4. Структура и слои

```
src/routes → src/controllers → src/services → src/repositories → PostgreSQL
                                   ↓
                              src/views (EJS) + client/ (React islands)
```

- `controllers` — HTTP: разбор входа, Zod, вызов сервиса, статус, шаблон/JSON. Максимум 40 строк на обработчик.
  Никакого SQL, формул и `req` внутри сервисов.
- `services` — математика и правила. Чистые функции там, где возможно; принимают примитивы/объекты, возвращают
  view-model. Не знают про Express.
- `repositories` — только SQL и маппинг. Параметризованные запросы, никакой конкатенации. Один репозиторий —
  одна таблица/агрегат.
- `views` — только отображение. Формулы в шаблонах запрещены; форматирование через `src/lib/format.js`.
- `client/` — React-острова. Начальные данные через `data-props` (JSON в атрибуте, экранированный), мутации —
  через `/api/v1`.
- Общие ошибки: классы `AppError`, `NotFoundError`, `ForbiddenError`, `ValidationError`; центральный error middleware.
  Никаких `catch (e) {}`.

Структура каталогов — §5 спеки. Новые файлы кладутся по слоям, не в корень.

## 5. Деньги, даты, числа

- Деньги — **целые копейки**, поля `*_cents`, `BIGINT`. Во float не переводить никогда. В API — копейки + `BYN`.
- Ввод сумм: принимать `1 234,56` и `1234.56`; отрицательные отклонять.
- Вывод: `1 234,56` + графический знак НБРБ. Символ — только через `<span class="byn">BYN</span>` и шрифт
  `public/fonts/nbrb.woff2`; не вставлять `₽`, `$`, `руб.`.
- Даты событий — `timestamptz` UTC; календарные — `date`. Границы периодов и когорты — Europe/Minsk.
- «Сегодня» для расчётов — **data anchor**: `MAX(daily_stats.stat_date)`, а не системные часы. Периоды по умолчанию,
  окна алертов и горизонты считаются от него; в интерфейсе подпись «Данные по …». Подробности — метрик-спека §0.1.
- Числовые таблицы и KPI — `font-variant-numeric: tabular-nums`, выравнивание вправо.
- Проценты: 1–2 знака, знак числа сохраняется (`+12,4%`, `−8,1%` — минус типографский).
- `null` — честное «нет данных»; не подменять нулём. В UI «—» + подсказка.

## 6. Дизайн

Стиль — Seline: тёплая бумага, hairline-границы, один cyan-акцент. Полный референс — `DESIGN (3).md`,
обязательные токены:

```
--color-stone-canvas #fafaf9   --color-pure-white #ffffff
--color-stone-border #e8e6e5   --color-stone-muted #d6d3d1
--color-ash-gray #a8a29e       --color-warm-gray #78716c
--color-ink-black #0c0a09      --color-soot #1c1917
--color-sky-wash #c1e1f7       --color-cyan-signal #3ba6f1
--color-cyan-edge #3398e1
--font-display 'Inter Tight'   --font-body 'Inter'
--radius-cards 10px  --radius-feature 16px  --radius-pill 9999px
--shadow-card 0 4px 16px rgba(0,0,0,.05)
--page-max 1200px  --section-gap 96px
```

Правила:
- фон страницы только `#fafaf9`, карточки только `#ffffff`;
- заголовки — Inter Tight 400, отрицательный трекинг; тело — Inter 400 14px/1.64;
- **один** cyan-filled элемент на экран (главный CTA); вторичные — ghost-пилюли с hairline;
- один highlight-span на заголовок (текст `#3398e1` на `#c1e1f7`), не больше;
- границы 1px — основная структура; тени только у всплывающих/preview-карточек;
- статусы: `healthy #2f7d5f`, `watch #a16207`, `risk #b91c1c` — только точки/текст/тонкие бары, не заливки кнопок;
- без градиентов, glassmorphism, неона, эмодзи в UI. Иконки — outline 1–1.5px;
- сетка 4px, отступы не равномерные: группировка через 8/12/16, разделение секций 32/48/96;
- тексты живые, короткие, без канцелярита: «Покажем, куда уходят деньги», а не «Осуществляется отображение».

Состояния обязательны для каждого экрана и виджета: loading (skeleton, не спиннер на весь экран), empty
(объяснение + действие), error (что случилось + retry), partial data (пометка «неполные данные»).

## 7. Графики

- Только Recharts, только SVG, никаких canvas-библиотек и пирогов/3D.
- Тема одна: `client/lib/chartTheme.js`; цвета — из токенов, не хардкодить в компонентах.
- Сетка — 1px `#e8e6e5`, оси и подписи — 12px `#78716c`, без рамок вокруг графика.
- Главный ряд — `#3ba6f1` (2px), вспомогательные — stone; выделенный канал — cyan, остальные — приглушённые.
- Tooltip — белая карточка, hairline, `--shadow-card`, значения в BYN.
- У каждого графика: заголовок-вывод, подпись периода, единицы, пустое состояние, `aria-label` и таблица-дубль
  данных (визуально скрытая или раскрываемая).
- Оси: компактные суммы (`12,4 тыс.`), без дублирования валюты в каждой точке.
- Не более 4 серий на линейном графике; больше — фильтр или small multiples.

## 8. SEO и публичные страницы

- SSR обязателен для `/`, `/login`, юридических страниц. Приложение `/app/*` — `noindex`.
- У каждой индексируемой страницы: уникальные `title` (≤60), `description` (≤160), canonical, OG/Twitter,
  `og:image` (из БД/`media_assets`), `lang="ru"`.
- Семантика: один `h1`, `header/nav/main/footer`, осмысленные ссылки, alt у изображений, `width/height`.
- JSON-LD `WebApplication` и `Organization` на лендинге; `sitemap.xml` и `robots.txt` — из приложения.
- Лендинг не содержит вымышленных отзывов и цифр, которых нет в демо; кейс «Зёрна» помечен как демонстрационный.
- Никаких CDN: шрифты, скрипты и изображения — локально, чтобы демо работало офлайн.

## 9. Безопасность

- Пароли — argon2id, минимум 10 символов; не логировать пароли, токены, `cookie` и содержимое сессий.
- Сессия: httpOnly, sameSite=lax, secure в production, regenerate при логине, TTL 8 ч.
- CSRF-токен обязателен для всех небезопасных методов, включая `fetch` (заголовок `X-CSRF-Token`).
- RBAC на каждом маршруте: `requireAuth`, `requireRole('admin')` и т.п. Скрытие кнопки не заменяет проверку.
- SQL — только параметризованный. HTML — только экранированный (`<%= %>`), `dangerouslySetInnerHTML` запрещён.
- Валидация на сервере — обязательна, даже если есть на клиенте.
- Rate-limit на логин и импорт; лимиты размера тела/файла.
- Секреты — только `.env`, в репозиторий не попадают. `.env.example` без реальных значений.
- Любое значимое действие (вход, смена роли, импорт, изменение целей, удаление, экспорт) — в `audit_log`.

## 10. Тесты и проверка

- Формулы — только по метрик-спеке, с ручными фикстурами и краевыми случаями (0, null, неполная когорта).
- Юнит-тесты: сервисы. Интеграционные: маршруты, RBAC, CSRF, импорт, миграции. E2E: agent-browser.
- Новый баг → сначала падающий регрессионный тест, потом фикс.
- Перед сдачей задачи: `npm test` (или затронутые файлы) + ручная проверка экрана.
- UI-проверка только через реальный браузер: запустить сервер, открыть, кликнуть. Скриншот без клика — не проверка.
- Тесты не должны ходить в прод-БД: отдельная `TEST_DATABASE_URL` или схема `test_*`.

### agent-browser

```bash
agent-browser open http://localhost:3000/login

agent-browser click @e3
```

Правила: проверять консоль на ошибки, проверять мобильную ширину (`agent-browser resize 390 844`),
не коммитить скриншоты вне `docs/`.

## 11. Рабочий процесс агента

1. Прочитать спеку и `AGENTS.md`; уточнить неоднозначности **до** кода.
2. Работать в рамках задачи; не добавлять фичи «заодно».
3. Проверять гипотезы в браузере/psql, а не по памяти.
4. Найденные не-критичные улучшения — в `IMPROVEMENTS.md` (в корне, под версионным контролем), не в код.
5. Критичную проблему (безопасность, потеря данных, сломанный сценарий) — остановиться и сообщить.
6. Отчёт: что сделано, как проверено (команды/скриншоты), что осталось, какие решения приняты.
7. **Коммит — в конце каждой задачи плана**, от имени владельца репозитория (git config уже настроен). Формат:
   `type: краткое описание` (feat, fix, refactor, chore, docs, style, perf, test, ci, build, a11y), тело — почему,
   что отвергнуто. Пуши, теги и релизы — только после явного одобрения человека.
8. Не оставлять мёртвый код, `console.log`, закомментированные блоки, временные флаги.

## 14. Переносимость

Репозиторий должен запускаться у любого человека с чистого клона, а не только на машине автора.

- В отслеживаемых файлах нет локальных имён пользователей, домашних путей, паролей и имён БД конкретной машины.
  Всё, что зависит от окружения, читается из `.env`; `.env` в git не попадает.
- `.env.example` — рабочий шаблон: значения по умолчанию совместимы с локальным PostgreSQL и Docker
  (`postgres://postgres:postgres@localhost:5432/...`), рядом комментарий, как заменить под свой стенд.
- `npm run db:setup` создаёт dev/test БД идемпотентно из URL в `.env`; повторный запуск не падает.
- Тесты используют только `TEST_DATABASE_URL`; не требуют суперпользователя, конкретной локали или имени роли.
  Ошибки БД проверяются по SQLSTATE, а не по тексту сообщения.
- README описывает путь с нуля: Node, PostgreSQL (или Docker), `.env`, setup, migrate, seed, build, start, демо-вход.
- Docker-путь обязан подниматься с дефолтами без правок файлов; секреты — через окружение.
- Перед сдачей этапа — проверка на чистой БД (drop/create) и, где возможно, на второй машине/контейнере.

## 15. Запрещено

- TypeScript, `.ts`/`.tsx`, `ts-node`, `tsx`.
- Любой CSS помимо `public/css/app.css`; Tailwind, Bootstrap, MUI, styled-components, CSS-модули.

- Коммиты и пуши без одобрения человека (коммиты — по §11.7).
