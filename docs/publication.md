# Публикация репозитория «Метрика»

Документ готовит репозиторий к передаче владельцу: что вставить в поля GitHub, что проверить до тега `v1.0.0` и
что остаётся за владельцем. **Тег и пуш отсюда не выполняются** — это локальная подготовка текста и проверок.

Состояние на 24.11.2026: задачи M6 T1–T7 закрыты, публикационный пакет добавлен задачей T8. Доказательства прогонов
(Compose, E2E, бэкапы, native-путь) лежат в [журнале M6](screenshots/m6/README.md); порядок развёртывания —
в [руководстве по развёртыванию](deployment.md), работа с экранами — в [руководстве пользователя](user-guide.md).

## 4. Статус лицензии

**Статус лицензии:** плейсхолдер. `LICENSE` содержит только уведомление об авторских правах и прямо говорит, что
лицензия не выдана; выбор лицензии — решение владельца. Пока файл не заменён, тег `v1.0.0` не ставится.

`tests/unit/publication.test.js` различает два состояния файла, поэтому замена плейсхолдера не ломает тест:

- **плейсхолдер** (в тексте есть `No license is granted yet`) обязан содержать `Copyright`, «All rights reserved»
  и не выдавать лицензию — иначе тест падает;
- **выбранная лицензия** — любой непустой файл с `Copyright` или названием известной лицензии
  (MIT, Apache, BSD, GPL/LGPL, ISC, MPL, Unlicense, Creative Commons, Proprietary).

Что сделать владельцу — один из вариантов:

1. **Проприетарная лицензия.** Заменить плейсхолдер явным текстом: правообладатель и год, «All rights reserved»,
   условия использования или прямой запрет на копирование и распространение без письменного разрешения.
   Просто оставить плейсхолдер — это не выбор проприетарной лицензии, а отсутствие решения: файл говорит, что
   лицензия ещё не выдана.
2. **MIT.** Заменить содержимое `LICENSE` стандартным текстом MIT с годом 2026 и именем правообладателя.

После замены выполните `npx vitest run tests/unit/publication.test.js`.

## 5. Предлагаемый тег v1.0.0

**Предлагаемый тег v1.0.0** (аннотированный, на коммит с задачей T8):

```text
v1.0.0
M6 delivery: Docker, encrypted backups, deployment and user guides
```

Тело аннотации должно остаться дословно таким: оно называет то, что реально вошло в M6, и не обещает фич M6+.
Команды для владельца (после приёмки и закрытия блокеров из §8):

```bash
git remote add origin <URL-репозитория>
git push -u origin main
git tag -a v1.0.0 -m "M6 delivery: Docker, encrypted backups, deployment and user guides"
git push origin v1.0.0
```

**Тег и пуш — только владелец.** Агент не создаёт remote, не пушит и не ставит тег; проверка чистого клона
(`npm run check:fresh`) работает локально от записанного SHA и remote не требует.

## 7. Известные ограничения

- **Один экземпляр приложения.** Лимитеры входа хранятся в памяти процесса, сид демо-данных не сериализован между
  репликами, а фоновых задач нет. Горизонтальное масштабирование `app` не поддерживается: нужен общий store
  лимитеров и блокировка сида.
- **Демо-пароль опубликован намеренно.** `admin@metrika.by` / `Metrika2026!` — учебный стенд. Перед публичным
  запуском смените пароли, `SESSION_SECRET` и включите HTTPS с `COOKIE_SECURE=true`; без этого стенд не production.
- **Атрибуция только на уровне каналов.** Кампанийного фильтра в атрибуции, алертах и сценариях нет: это отдельный
  путь агрегации, а не недостающая кнопка.
- **Оптимизатор без ограничений на канал.** Общий недельный бюджет распределяется по KKT с одним потолком 3×;
  per-channel min/max и water-filling не реализованы. Сценарии нельзя редактировать и удалять — только сохранить
  новый снимок.
- **Алерты помнят последнюю проверку, а не первое срабатывание.** `alerts.detected_at` перезаписывается при
  пересчёте; `first_detected_at`/`resolved_at` потребуют миграции.
- **Обложка из БД не подключена к метатегам.** `og:image` — статический committed PNG. Если администратор загрузит
  другую обложку, лендинг продолжит отдавать старую, пока `homePage` не станет асинхронным.
- **Резервное копирование логическое.** `pg_dump -Fc` + AES-256-GCM, retention по mtime; WAL-архивации и
  point-in-time recovery нет. Восстановление проверяется в scratch-базу, а не на живом стенде.
- **Импорт ограничен 10 000 строк и работает по строкам.** Для демо-объёма этого достаточно; большие наборы
  потребуют пакетных вставок.
- **Медиа и пересчёт алертов без отдельных лимитов/аудита.** Загрузка медиа ограничена 1 МБ на запрос, но без
  per-user счётчика; пересчёт алертов не пишет `audit_log` (R1/R2 в [`docs/security-audit.md`](security-audit.md)).
- **Кросс-браузерная матрица неполная.** Chromium проверен E2E; Firefox, Opera/Yandex, Windows 10 и Docker Desktop
  здесь недоступны и не заявляются проверенными.

## 8. Что остаётся владельцу

Блокеры тега (пока открыт хотя бы один, `v1.0.0` не ставится):

1. **Решение по лицензии** — §4.
2. **Подпись по Firefox** — ручной прогон по `docs/screenshots/m6/README.md` §9; скриншоты `firefox-*.png` только
   с указанием автора прогона.
3. **Windows 10** — native smoke, импорт, бэкап/восстановление, Планировщик заданий по `docs/deployment.md` §5.
4. **Docker Desktop** — `docker compose up --build` на Windows; Linux-прогон Compose из T1 не заменяет его.
5. **Публичный TLS-стенд** — HTTPS, HSTS, `COOKIE_SECURE=true`, проверка `Set-Cookie`.

Действия владельца после приёмки: вставить описание и темы (§1–2), загрузить social preview (§3), добавить remote,
выполнить пуш и поставить тег (§5).

Вне репозитория и вне задач агента: пояснительная записка, диаграммы IDEF0/UML, слайды и демо-сценарий защиты.
