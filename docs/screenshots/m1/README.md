# M1 — журнал браузерной проверки

Дата прогона: 21.11.2026. Стенд: `http://localhost:3000`, PostgreSQL 18, сид с якорем данных **20.11.2026**.
Браузер: Chromium через `agent-browser` (headless), сессия `metrika-m1-task8`. Все переходы по ссылкам и кнопкам
сделаны реальными кликами; прямые URL открывались только там, где проверялся серверный RBAC вне навигации.

## Как воспроизвести

```bash
# 1. Чистая база и данные
npm run db:setup          # создаёт БД из DATABASE_URL / TEST_DATABASE_URL
npm run migrate
npm run seed

# 2. Приложение
npm run dev               # http://localhost:3000, /health → 200

# 3. Браузер
agent-browser --session metrika-m1-task8 set viewport 1440 1000
agent-browser --session metrika-m1-task8 open http://localhost:3000/
```

Пароль всех демо-аккаунтов — `Metrika2026!`.

## Консоль

После каждого экрана выполнялись:

```bash
agent-browser --session metrika-m1-task8 console
agent-browser --session metrika-m1-task8 errors
```

Обе команды пусты на лендинге (desktop и mobile), входе, дашборде, списке пользователей, 403 analyst/viewer,
404 и после клика «На главную». Ошибок JS и неудачных запросов нет.

## Что осталось за рамками снимков

- 500-я страница недоступна по реальному маршруту; она проверена отдельным harness в задаче 7 и покрыта
  запиской в `IMPROVEMENTS.md`.
- Мобильный каркас приложения: в этом прогоне дашборд повторно открыт на 390×844 — `scrollWidth === 390`,
  навигация свёрнута до метки «Разделы» и раскрывается кликом, ошибок в консоли нет. Таблица внутри
  `.table-wrap` проверена в задаче 7.
- Публичная шапка на страницах 403/404/500 по-прежнему показывает «Войти» вошедшему пользователю — известное
  отложенное улучшение, не ошибка M1.
