# «Метрика» — дорожная карта реализации

> **Для агентов:** детальный план этапа M1 — в `2026-11-21-metrika-m1-foundation.md`. Планы M2–M6
> детализируются в начале соответствующего этапа по фактическим интерфейсам, чтобы не планировать фантомы.
> Общие правила — `AGENTS.md`, спеки — `docs/superpowers/specs/`.

**Цель:** довести приложение от пустого репозитория до демонстрируемого продукта с корректными метриками,
проверенным интерфейсом и развёртыванием на Windows 10.

**Архитектура:** Express MVC (routes → controllers → services → repositories → EJS) + React-острова
через Vite; PostgreSQL; сессии в БД; один `public/css/app.css`.

**Срок:** 20.12.2026. Работа идёт этапами; каждый этап заканчивается зелёными тестами, браузерной проверкой
и коммитом.

## M1 — фундамент

1. **Каркас и здоровье**: package.json, env с валидацией, pino, классы ошибок, пул PG, `/health`, grace shutdown.
2. **Схема БД**: миграции всех 15 таблиц, раннер с advisory lock, тесты идемпотентности и FK.
3. **Сид**: 8 каналов, 32 кампании, 14 месяцев статистики, 4 000 клиентов, 9 000 заказов, касания, 3 пользователя.
4. **Дизайн-система**: `app.css` с токенами Seline, шрифты Inter/Inter Tight/НБРБ локально, guard-тест «один CSS».
5. **Лендинг**: hero, формулы, возможности, FAQ, SEO (canonical, OG, JSON-LD), robots/sitemap.
6. **Авторизация**: сессии в PG, argon2id, CSRF, rate-limit, RBAC на 3 роли, безопасный `next`.
7. **Каркас приложения**: сайдбар по правам, topbar с data anchor, пустой дашборд, пользователи (read-only), 403/404/500.
8. **E2E-смоук**: три роли через agent-browser, консоль, 390px, скриншоты, README.

Критерий: `npm run migrate && npm run seed && npm run dev`, вход тремя ролями, лендинг с корректным SEO,
`npm test` зелёный, ноль ошибок в консоли. Чистый клон с `cp .env.example .env` и `npm run db:setup`
запускается без правок кода под конкретную машину.

## M2 — данные и администрирование

1. Каналы: список, создание, редактирование, архивирование; цели канала; аудит.
2. Кампании: CRUD, фильтры по каналу/статусу, привязка к каналу, запрет удаления с данными.
3. Пользователи: создание с временным паролем, смена роли, блокировка, сброс пароля; нельзя заблокировать себя.
4. Цели: CRUD по метрике/каналу/периоду, проверка пересечений.
5. Импорт CSV: 4 типа, шаблоны, валидация Zod, транзакция, отчёт ошибок, лимиты, аудит.
6. Экспорт CSV: текущие фильтры, BOM, корректные заголовки, аудит.
7. Медиа: загрузка обложки/аватара в `media_assets` (BYTEA), отдача `/media/:id` с ETag и кэшем, аудит.

Критерий: аналитик наполняет систему с нуля через интерфейс без psql; viewer получает 403 на мутации;
админ управляет ролями; каждое действие видно в аудите; изображение из БД отдаётся по `/media/:id`.

## M3 — движок метрик

1. `lib/money`, `lib/dates`, форматирование BYN, парсинг ввода — тесты.
2. Data anchor и reference-сервис.
3. CAC (канал, кампания, blended) + тесты нулей.
4. Когортный LTV 3/6/12, завершённые/незавершённые когорты.
5. Атрибуция first/last/linear с точной суммой до копейки.
6. ROMI, payback, LTV:CAC, health-статусы.
7. Рейтинг каналов с настраиваемыми весами.
8. Алерты (правила, severity, дедупликация).
9. Кривые насыщения и оптимизация бюджета (KKT + бисекция).

Критерий: каждая формула покрыта ручными фикстурами из метрик-спеки; сервисы не знают про HTTP;
никаких `NaN`/`Infinity` на границах.

## M4 — аналитика

1. Инфраструктура островов: Vite, манифест, `data-props`, API-клиент, тема графиков.
2. Дашборд: KPI, период, фильтры каналов, CAC/ROMI-линия, расходы, scatter CAC×LTV, вердикт.
3. Каналы: таблица, сортировка, health, sparkline, рейтинг с вкладом критериев.
4. Карточка канала: метрики, график, воронка, кампании.
5. Когорты: heatmap удержания + накопленный LTV.
6. Атрибуция: сравнение трёх моделей, дельта.
7. Общие состояния (skeleton/empty/error), доступные таблицы-дубли графиков.

Критерий: все экраны на сиде, фильтры меняют данные, графики читаемы на 1280 и 390, консоль чистая,
каждый график имеет вывод-заголовок и доступное представление.

## M5 — решения

1. Сценарии: API, сохранение, список, аудит.
2. UI сценария: бюджет, каналы, слайдеры, кривые насыщения, до/после, предупреждение экстраполяции.
3. Рекомендация бюджета: оптимальные доли, прирост, объяснение.
4. Алерты: пересчёт, фильтры, закрытие с аудитом.
5. Цели: факт/план/отклонение, bullet-график.
6. Экспорт отчётов из всех экранов.

Критерий: сценарий сохраняется и воспроизводится; рекомендация объяснима; алерты не дублируются;
цели показывают отклонение по data anchor.

## M6 — полировка и сдача

1. Безопасность: полный аудит маршрутов, CSRF, rate-limit, сессии, заголовки, секреты.
2. Доступность: клавиатура, контраст, подписи, таблицы-дубли, 390px.
3. SEO: мета, OG-картинка, JSON-LD, sitemap, `noindex` приложения.
4. Производительность: EXPLAIN трёх тяжёлых запросов, индексы, N+1, размер бандлов.
5. E2E-матрица: 3 роли × основные сценарии + ошибки (403/404/500/импорт).
6. Docker + compose, инструкция Windows 10, бэкап/восстановление, проверка на чистой машине.
7. README, руководство пользователя, скриншоты, `IMPROVEMENTS.md`.
8. Финальное ревью, тег версии, демо-прогон.

Критерий: сдача по чек-листу `2026-11-21-assignment-traceability.md` §7. `docker compose up` поднимается
с дефолтами без правок файлов; проверено на чистой БД и, где возможно, на второй машине.

## Правила этапа

- Один этап — один набор коммитов по задачам; тег после приёмки этапа — только с одобрения.
- Перед этапом план детализируется; после — отчёт: что сделано, как проверено, что осталось.
- Найденное не-критичное — в `IMPROVEMENTS.md`, критичное — стоп и сообщение.
- Автотесты + agent-browser; скриншот без клика проверкой не считается.
